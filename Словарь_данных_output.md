# Словарь данных: остальные файлы `output/`

Для `output/master_dataset.csv` — отдельный документ, `Словарь_данных_master_dataset.md`. Здесь описаны все прочие файлы пайплайна: промежуточные (сырые по каждому источнику) и производные (валидация, цены, спред, снимок). Актуально на 2026-09-10.

---

## 01_faostat.csv — FAOSTAT, национальный уровень

**Скрипт:** `01_faostat.py`. **Строк:** 466. **Гранулярность:** (культура, показатель, год).

| Столбец | Тип | Описание |
|---|---|---|
| `year` | int | Год, 1992–2024 |
| `crop` | str | `Wheat`, `Barley`, `Maize (corn)`, `Sunflower seed`, `Rapeseed` |
| `indicator` | str | `Area harvested (ha)`, `Production (t)`, `Producer Price (USD/t)` |
| `value` | float | Значение показателя в единице `unit` |
| `unit` | str | Единица измерения (`ha`, `t`, `USD`) — берётся из ответа FAOSTAT как есть |
| `flag` | str | Флаг качества данных FAOSTAT (`A` = официальная цифра и т.д. — стандартные коды FAO) |
| `country` | str | Всегда `Kazakhstan` (после исправления бага с кодом страны, см. Отчёт §2.1 — код страны теперь **проверяется**, а не считается верным по умолчанию) |
| `source` | str | `FAOSTAT_QCL` (площадь/производство) или `FAOSTAT_PP1` (цены) |

## 02_worldbank_prices.csv / 02_prices_monthly.csv — мировые цены

**Скрипт:** `02_worldbank_prices.py`. Годовой файл: 36 строк (1990–2025). Помесячный: 432 строки.

| Столбец | Тип | Описание |
|---|---|---|
| `year`, `month`, `period` | — | `period` только в помесячном файле, формат `"1990M01"` |
| `wheat_hrw_usd_t` … `urea_fertilizer_usd_t` | float | USD/т — 10 товаров: пшеница HRW/SRW, ячмень, кукуруза, рапсовое/подсолнечное/соевое/пальмовое масло, DAP, карбамид |
| `months_count` | int | Только в годовом файле — сколько месяцев из 12 имели данные при усреднении (показатель полноты года) |
| `source` | str | `WorldBank_PinkSheet` (помесячный) / `WorldBank_PinkSheet_annual` (годовой) |

**Пропуски:** `barley_usd_t` (15.7% в годовом файле), `rapeseed_oil_usd_t`/`sunflower_oil_usd_t` (30.4%) — источник не публиковал эти котировки часть исторического периода, не ошибка сбора.

## 03_era5_climate.csv / 03_era5_monthly.csv — климат

**Скрипт:** `03_era5_climate.py`. Годовой (агрегат за вегетацию): 35 строк. Помесячный: 420 строк.

| Столбец | Тип | Описание |
|---|---|---|
| `time` | date | Только в помесячном файле — первое число месяца |
| `year`, `month` | int | — |
| `t2m_kelvin` / `gs_t2m_kelvin` | float | Температура воздуха 2м, K (`gs_`-префикс = агрегат апрель–сентябрь, в годовом файле) |
| `t2m_celsius` / `gs_t2m_celsius` | float | То же, °C |
| `precip_m`, `precip_mm` (+ `gs_` варианты) | float | Осадки, уже скорректированные на число дней в месяце (см. Отчёт §2.3 — без этого были бы занижены в ~28–31 раз) |
| `pot_evap_m`, `pot_evap_mm` | float | Потенциальная эвапотранспирация, та же поправка |
| `soil_water_l1`, `soil_water_l2` | float | Объёмная влажность почвы, м³/м³, слои 0–7см и 7–28см (не накопительная переменная, поправка на дни не нужна) |
| `solar_rad_jm2`, `solar_rad_mjm2` | float | Солнечная радиация, та же поправка на дни месяца |

**Единицы измерения совпадают с одноимёнными `gs_*`-столбцами в `master_dataset.csv`** — см. тот словарь для полного описания каждой переменной.

## 04_soilgrids_long.csv / 04_soilgrids_wide.csv — почва

**Скрипт:** `04_soilgrids.py`. Длинный формат: 640 строк (20 точек × 4 глубины × 8 свойств, полное покрытие). Широкий: 80 строк (точка × глубина).

**Про повтор при сбое:** SoilGrids REST API временами роняет отдельные запросы без системной причины (таймаут/5xx) — без повтора набор точек с данными был недетерминирован от запуска к запуску (обнаружено 2026-09-11: 17 из 20 точек в одном запуске, другие 17 — в следующем). `fetch_soilgrids_point()` теперь повторяет неудавшийся запрос до 3 раз с задержкой, кратной интервалу rate limit — с этим все 20 точек собираются стабильно.

| Столбец | Тип | Описание |
|---|---|---|
| `lat`, `lon` | float | Координаты точки сетки (шаг ~2°, зерновой пояс) |
| `depth` | str | `0-5cm`, `5-15cm`, `15-30cm`, `30-60cm` |
| `property` | str | Только в длинном формате: `phh2o`, `soc`, `bdod`, `clay`, `sand`, `silt`, `cec`, `nitrogen` |
| `value_raw` | float | Сырое целочисленное значение от API, ДО деления на `d_factor` |
| `value` | float | После деления на `d_factor` — физически корректное значение (см. Отчёт §2.4 про баг с `d_factor` vs `conversion_factor`) |
| `unit` | str | Единица от API (`pH*10`, `dg/kg` и т.д. — описывает МАСШТАБ сырого значения, не `value`) |
| `bdod` … `soc` | float | В широком формате — те же 8 свойств как отдельные столбцы, уже после конверсии. Единицы — см. `Словарь_данных_master_dataset.md`, раздел "Почва" |

## 10_district_price_snapshot.csv — ⚠️ иллюстративный демо-файл

**Скрипт:** `10_district_price_snapshot.py`. 177 строк (районы × культуры, где есть цена). **НЕ компонент методологии** — см. README, раздел "Методологическая позиция: районные данные (05) vs цена (08/09)", и предупреждение в самом скрипте.

| Столбец | Тип | Описание |
|---|---|---|
| `price_week_date_from/to` | date | Неделя цены — ОТЛИЧАЕТСЯ от `year` (год урожая); намеренный date-mismatch, не историческое соответствие |
| `notional_revenue_domestic_usd` | float | `production_ton × domestic_usd_per_t` — условная выручка при продаже на элеватор |
| `notional_revenue_export_usd` | float | То же для экспортной цены |
| `export_uplift_usd` | float | Разница — потенциальный выигрыш от экспорта вместо внутреннего рынка, на объём данного района |

Остальные столбцы — как в `05_kaz_stat_districts.csv` (без строки `"Область (итого)"` — исключена намеренно, см. докстринг скрипта) плюс `domestic_usd_per_t`/`export_usd_per_t` из 09.
