# Отчёт о сборе данных

**Проект:** Разработка рекомендательной системы для аграриев на основе методов анализа исторических данных посевных кампаний и рыночной динамики
**Период работы:** 2026-09-09 — 2026-10-05 (§2.1–2.7 описывают сбор 2026-09-09/10; §2.8–2.12 — районный уровень и рыночный слой, добавленные 2026-10-05)
**Статус:** пайплайн воспроизводим, провалидирован независимой кросс-проверкой и 84 автоматическими тестами данных (`python -m pytest`)

Этот документ описывает, **как именно** собирались данные для диссертации — источники, методологию сбора, обеспечение качества и найденные ограничения. В отличие от `README.md` (техническая инструкция по запуску скриптов), этот отчёт — нарративное описание процесса, пригодное как основа для раздела "Материалы и методы".

## 2. Источники данных и методология сбора

### 2.1. Производство — FAOSTAT (национальный уровень)

**Источник:** bulk-выгрузка FAOSTAT (`bulks-faostat.fao.org`), а не REST API — API периодически недоступен (ошибка 521), bulk-сервер — отдельная, более стабильная инфраструктура, которую использует официальный R-пакет FAOSTAT и Our World in Data.

**Метод:** скачивание полных датасетов QCL (Production_Crops_Livestock) и PP1 (Prices) целиком (33.9 МБ и 11.7 МБ), фильтрация по коду страны и по 5 целевым культурам (пшеница, ячмень, кукуруза, подсолнечник, рапс).

**Результат:** 466 записей, 1992–2024, 3 показателя (площадь, производство, цена производителя) × 5 культур.

**Критическая находка при валидации:** исходный код страны в скрипте (`KAZ_AREA_CODE = 63`) на самом деле соответствовал **Эстонии**, а не Казахстану — проверено прямым чтением сырого bulk-файла. Обнаружено не вручную, а автоматической кросс-валидацией (скрипт 07): доля региональных данных от "национального" итога доходила до 8900%, что физически невозможно. После исправления кода (на правильный **108**) добавлена автоматическая защита — скрипт теперь падает с понятной ошибкой, если название страны в полученных данных не содержит "Kazakhstan", вместо того чтобы молча доверять числовому коду.

### 2.2. Мировые цены — World Bank Pink Sheet

**Источник:** World Bank Commodity Markets (CMO Pink Sheet), лист "Monthly Prices" — стандартный академический источник мировых цен на сырьё, обновляется ежемесячно.

**Метод:** скачивание Excel-файла, парсинг по подтверждённым номерам столбцов (пшеница HRW/SRW, ячмень, кукуруза, масла — рапсовое/подсолнечное/соевое/пальмовое, удобрения DAP/карбамид), с автоматической проверкой, что название товара в найденном столбце действительно совпадает с ожидаемым (защита от смещения столбцов при обновлении формата файла источником).

**Результат:** 36 годовых записей (1990–2025) + помесячные данные. На момент сбора (2026-09-10) у источника ещё нет ни одного месяца 2026 года — учтено при построении спреда внутреннего/мирового рынка (см. §2.6).

### 2.3. Климат — ERA5-Land (Copernicus CDS)

**Источник:** ECMWF ERA5-Land Monthly Means через Copernicus Climate Data Store API.

**Метод:** загрузка по одному году за запрос (не всем диапазоном разом) для устойчивости к обрывам соединения — уже скачанные годы кэшируются локально и пропускаются при повторном запуске. Пространственное усреднение по bounding box зернового пояса Казахстана (N55 S49 W60 E78).

**Результат:** 420 месячных записей, 1991–2025, агрегировано до вегетационного периода (апрель–сентябрь).

**Найденная и исправленная ошибка:** для `product_type=monthly_averaged_reanalysis` Copernicus CDS отдаёт накопительные переменные (осадки, испарение, солнечная радиация) как **среднесуточную скорость за месяц**, а не как сумму за месяц — задокументированная, но неочевидная особенность ERA5 (подтверждено по официальной документации ECMWF: `tp[мм] = tp[м/сутки] × 1000 × N`, где N — число дней в месяце). Без этой поправки годовая сумма осадков по зерновому поясу получалась ~13 мм/год — уровень пустыни, а не степи. После исправления — ~350–400 мм/год, что соответствует реальной климатической норме региона. Дополнительное подтверждение: засушливые 2021–2022 годы (документированная региональная засуха) после исправления корректно показывают пониженные осадки.

### 2.4. Почва — SoilGrids v2.0 (ISRIC)

**Источник:** SoilGrids v2.0 REST API — глобальная база свойств почв с разрешением 250 м, построенная ISRIC методами машинного обучения; стандартный источник почвенных данных в литературе по прогнозированию урожайности.

**Метод:** запросы по сетке из 20 точек (шаг ~200 км) по зерновому поясу (Акмолинская, Костанайская, Северо-Казахстанская области), 4 глубины профиля, с соблюдением ограничения API в 5 запросов/минуту.

**Результат:** 68 записей (точка × глубина), 8 свойств почвы (pH, органический углерод, объёмная плотность, гранулометрия, азот, ёмкость катионного обмена).

**Найденная и исправленная ошибка:** поле пересчёта единиц измерения в реальном ответе API называется `d_factor`, а не `conversion_factor`, как предполагал изначальный код — из-за этого коэффициент пересчёта не применялся вообще ни к одному из 8 свойств. Глина+песок+ил суммировались в ~1000 вместо ~100% (физически бессмысленно), pH показывал 65–80 вместо 6.5–8.0. После исправления все значения — в физически корректных диапазонах (pH 6.9–7.6, объёмная плотность 0.99–1.24 г/см³, гранулометрия суммируется в 100% ± округление).

### 2.5. Региональное производство — stat.gov.kz (область + район)

**Источник:** Бюро национальной статистики РК, раздел "Статистика регионов" → область → "Динамические ряды" — у каждой области есть страница с прямыми ссылками на xlsx-файлы исторических рядов. Официального REST API для растениеводства нет; раздел "Электронные таблицы" на общем сайте отдаёт только последние 1–2 релиза без архива, поэтому использован областной раздел, где обнаружился стабильный архив с 1990/1991 года.

**Метод:** прямое скачивание xlsx-файлов по числовым ID элементов (кэшируются локально), парсинг таблиц с разной внутренней структурой у разных областей:
- Костанайская и Северо-Казахстанская области публикуют отдельные файлы по каждой культуре (пшеница, ячмень, кукуруза, подсолнечник) с разбивкой по районам.
- Акмолинская область публикует растениеводство на уровне крупных групп ("зерновые и бобовые", "масличные") — но, как выяснилось при повторном разборе, файлы группы содержат встроенный подблок "из них: пшеницы" / "из них: семена подсолнечника" с ПОВТОРНОЙ районной разбивкой уже для конкретной культуры. Это позволило извлечь Пшеницу и Подсолнечник Акмолинской области как самостоятельные культуры, а не только как часть агрегированной группы — закрыв тем самым исходно задокументированный пробел методологии.

**Результат:**
- Областной уровень (`05_kaz_stat.csv`): 382 записи, 1990–2025, культуры — Пшеница, Ячмень, Кукуруза, Подсолнечник (все три области, где доступно) + Зерновые/Масличные группы (только Акмолинская, где детализация по отдельным культурам отсутствует у источника — ячмень и кукуруза Акмолинской области).
- Районный уровень (`05_kaz_stat_districts.csv`): 6067 записей, 57 районов трёх областей.
- Рапс регионально не публикует ни одна из трёх областей — единственный источник по рапсу в проекте остаётся национальный FAOSTAT (§2.1). Это задокументированное структурное ограничение источника, а не пропуск методологии.

**Найденные и исправленные ошибки** (все — до попадания в итоговый датасет, пойманы автоматической валидацией, не постфактум):
1. Единицы измерения на сайте меняются посреди временного ряда без явной пометки по годам (например, тысячи гектаров → штучные гектары начиная с определённого года) — добавлен автоматический детектор устойчивых скачков масштаба (50×+, не откатывающихся обратно), который отбрасывает ненадёжный ранний период вместо того, чтобы оставить заведомо неверный порядок величины.
2. Один файл может содержать ДВЕ разных подписи единицы измерения в одной строке для разных диапазонов столбцов (например, "тыс. тонн" для старых лет и "центнеров" для новых) — детектор единиц переписан на поколоночный, а не общий на весь лист.
3. Падежные формы в подписях единиц ("центнеров" vs "в центнерах", "тыс. гектар" vs "тыс.га") ломали точное совпадение строки — сопоставление переписано на регулярные выражения по неизменяемой основе слова.
4. При добавлении районной разбивки детектор скачков масштаба (пункт 1) ложно срабатывал на малых районных сериях, где обычная волатильность второстепенной культуры выглядела как "скачок единицы измерения" — решение об отсечке переписано так, чтобы приниматься по устойчивой агрегированной серии ("область целиком"), но применяться ко всем районам той же группы.
5. Скрытые подблоки "из них: <культура>" внутри файлов Акмолинской области (см. выше) изначально ТОЛЬКО мешали — их числа задваивали сумму по районам, если не отсечь корректно. При переписывании парсера для извлечения этих подблоков как самостоятельных данных была внесена регрессия (снятие защитного условия `include_districts` при рефакторинге), которая привела к повторному задваиванию сумм — поймано по аномалии в логах ("скачок 1991→1991" — один и тот же год дважды в ряду) до того, как ошибочные данные попали в датасет.

### 2.6. Внутренний рынок Казахстана — grainunion.kz

**Источник:** сайт ОЮЛ "Зерновой союз Казахстана" (`grainunion.kz`), раздел новостей, статьи "Еженедельный обзор ценовой ситуации на зерновом рынке Казахстана".

**Как найден:** исходно рассматривался `apk-inform.com` — коммерческий агрегатор с публичным (без логина) AJAX-виджетом цен, но в бесплатном доступе там нашлось только 2 экспортные позиции по Казахстану в USD (пшеница DAP ст. Сарыагаш, ячмень FOB порт Актау) — внутреннего тенгового рынка нет, вероятно, за подпиской. Старый адрес Зернового союза (`gsc.kz`) не работает (404 на всех путях, домен заброшен). Текущий адрес найден через поиск и подтверждён как действующий.

**Метод:** обход разделов новостей `/ru/news/32` с фильтрацией по заголовку "еженедельный обзор", парсинг структурированных буллет-пунктов вида `▪️Пшеница 3 кл (кл-на 23-24%) - 88 - 92 ▶️ (0)` регулярными выражениями (не NLP, так как формат структурирован). Дополнительно извлекаются курсы валют Нацбанка РК за ту же неделю — из того же текста обзора, что даёт точный перевод тенге→USD без внешнего FX-источника.

**Важное методологическое уточнение:** структурированный формат обзоров стартовал только 25.05.2026 — проверено постранично по всему архиву новостей (который в остальном уходит в 2019 год, но состоит из разрозненных пресс-релизов и анонсов конференций, не еженедельных ценовых сводок). На 2026-09-10 доступно 12 выпусков внутренних цен (~3.5 месяца). Скрипт спроектирован для периодического перезапуска — при каждом новом запуске дозаписывает только новые выпуски, не скачивая уже собранные заново; история будет накапливаться со временем.

**Результат:** 231 запись из 12 выпусков — внутренние цены EXW-элеватор (пшеница 3–5 класса с разбивкой по клейковине, ячмень фуражный, семена льна) в тыс. тенге/т и экспортные котировки в USD/т, плюс курсы валют за ту же неделю.

### 2.7. Спред внутренний/экспорт/мировой рынок

**Метод:** для каждой недели считается (а) спред "экспорт минус внутренняя цена" (прямое сравнение внутри Казахстана, одна культура, одна неделя, курс за ту же неделю) и (б) спред "внутренняя цена минус мировой бенчмарк World Bank" (внутренняя цена переводится в USD по курсу той же недели). Из-за лага публикации World Bank Pink Sheet (последний доступный месяц на 2026-09-10 — декабрь 2025) для мировой цены используется последнее известное значение через as-of merge — с явной пометкой в данных, на сколько месяцев оно устарело относительно даты обзора, а не тихий NaN и не выдача устаревшего значения за актуальное.

**Результат на 2026-09-10:** экспорт в среднем на **+21%** дороже внутреннего рынка; внутренняя цена — на **-8.4%** ниже мирового бенчмарка (устаревшего на ≤8 месяцев).

### 2.8. Индекс цен производителей (скрипт 11)

**Источник:** динамический ряд stat.gov.kz «Индекс цен производителей на отдельные виды продукции сельского хозяйства» (элемент 1644), годовой, 1992–2025. **Метод:** разбор двух блоков листа (к декабрю предыдущего года и среднегодовой к среднегодовому), цепной уровень с базой 2015 = 100. **Ограничение:** национальный ряд и только две товарные группы по растениеводству (зерновые и масличные), поэтому отдельных индексов для пшеницы или подсолнечника нет. Индекс в районный master присоединяется по году, не по региону.

### 2.9. Координаты районов (скрипт 12)

**Зачем:** в районных рядах (05) есть только названия районов, а для районного климата и почвы нужны координаты. **Метод:** геокодирование центроидов границ районов через OSM Nominatim (не чаще 1 запроса в секунду, результаты кэшируются в `output/district_coords_cache.json`). Для каждой найденной точки проверяется попадание в bbox своей области: это защищает от омонимов (Есильский район есть и в Акмолинской, и в Северо-Казахстанской областях). Названия нормализуются (`район`, `г.а.` и др.), два написания «Косшы» сводятся в один район.

**Найденная проблема:** для Енбекшильдерского района геокодер вернул координаты соседнего района Биржан сал. Скрипт теперь исключает районы с совпадающими координатами: чужой климат хуже честного NaN. У исключённого района 30 строк (все — групповые масличные). Координаты районов им. Г. Мусрепова (53.05, 66.05) и Айыртауского (53.19, 68.07) независимо не проверялись и требуют сверки на карте.

### 2.10. Климат и почва на уровне района (скрипты 13 и 14)

**Климат (13).** В годовых NetCDF-файлах, скачанных скриптом 03, сохранена вся сетка ERA5-Land 0.1°; усреднение по bbox делается лишь после чтения. Поэтому повторная загрузка с CDS не потребовалась. Для каждого района берётся среднее по окну ±0.2° вокруг центроида (~5×5 ячеек), накопительные переменные пересчитываются из среднесуточной скорости в сумму за месяц (та же поправка, что в §2.3). Считаются 22 агроклиматических признака (21 числовой и флаг `pet_suspect`): температура, осадки и испарение по вегетации и подпериодам (май–июль, июнь–август), влажность почвы по месяцам, градусо-дни, осадки холодного периода, зимняя температура перед посевом, индексы засушливости.

**Найденные и исправленные проблемы:**
1. *Потенциальное испарение у озёр.* ERA5-Land даёт над озёрами и мокрыми ячейками 20–40 мм/сут в июне против ~9 мм/сут над сушей. У района М.Жумабаева окно целиком попало в такие ячейки: ~3250 мм за сезон при норме ~1300 мм. Найдено при написании тестов диапазонов. Для таких районов (испарение > 1.8× медианы всех районов за год) признаки испарения заменены на NaN и поставлен флаг `pet_suspect`. Осадки и температура остаются.
2. *Утечка из будущего в `winter_t2m_c`.* Первая версия считала зиму по календарному году и захватывала декабрь после уборки. Теперь это декабрь предыдущего года плюс январь и февраль; закреплено регрессионным тестом.

**Почва (14).** Запрос SoilGrids v2.0 в точке центроида каждого района (повторно используются функции скрипта 04, включая исправление `d_factor`). Для каждого свойства считаются слой 0–30 см (взвешено по толщине слоёв 5/10/15 см) и слой 30–60 см. Для 10 точек (в основном города и районы с озёрами) центроид попал в маску SoilGrids и API возвращает пустой ответ; скрипт ищет ближайшую точку со сдвигом (чаще ~11 км на север). Почва остаётся приближением и статична: различает районы, но не годы.

### 2.11. Районный master-датасет (скрипт 15)

Соединяет районные ряды (05), климат (13), почву (14), мировые цены и индексы цен по году (02, 11) и региональные цены (16). Строка = (область, район, культура, год). Лаги и скользящие средние считаются по календарному году внутри (район, культура) строго по прошлым годам.

**Санитарная очистка цели** (все исправления помечены флагами, исходные значения не теряются в источнике):
- `area_suspect` (393 строки): площадь отличается от медианы своего (район, культура) более чем в 20 раз или не сходится с урожайностью и сбором. Причина — смена единиц измерения в источнике (тыс. га ↔ га), которую детектор скрипта 05 ловит не во всех случаях. Пример: Биржан сал, пшеница, 2000 год: `area_ha = 81.6` вместо ~81 600.
- `yield_derived` (125 строк): урожайность посчитана как сбор/площадь там, где источник её не дал; для строк с подозрительной площадью такое восстановление отброшено.
- `yield_outlier` (44 строки): урожайность ≤0, >8000 кг/га или восстановлена из площади <50 га заменена на NaN. Один случай был 1.6 млн кг/га.
- Опубликованная урожайность в 15% строк расходится с `сбор/площадь` более чем на 10%: источник считает урожайность на убранную площадь, а `area_ha` — посевная. Это не ошибка, но цель нельзя восстановить из площади.

### 2.12. Региональные цены производителей (скрипт 16)

**Источник:** выпуск stat.gov.kz «Индексы цен и цены в сельском хозяйстве в Республике Казахстан» (ежемесячный), таблица «5. Средние цены производителей на продукцию сельского хозяйства по регионам» (тенге за тонну; пшеница, ячмень, кукуруза, подсолнечник и др.; 17 регионов и страна). Это цены фактической реализации за месяц, а не биржевые котировки.

**Как найден архив:** страница `/spreadsheets/` показывает только 10 последних выпусков, но GET-параметры её фильтра (`?name=19100&year=<год>`) отдают весь архив. Для этой серии выпуски есть **с октября 2022 года** (48 выпусков на 2026-09); раньше в этой серии данных нет. Старые выпуски отдаются как `.xls`, новые как `.xlsx` (сигнатуры различаются).

**Метод:** список выпусков по годам, скачивание в кэш `output/stat_prices_cache/`, поиск листа по заголовку, явная проверка единиц («тенге за тонну»), разбор матрицы «культура × регион». Значение «x» (конфиденциально: мало сделок) и «-» дают NaN.

**Найденные и исправленные проблемы:**
1. 35 из 48 выпусков отдаются как `.xls` (остальные 13 — `.xlsx`); первая версия принимала только `.xlsx`.
2. В выпуске за июль 2026 название региона записано слитно («СевероКазахстанская»); разбор не узнавал его, и СКО выпадала из ряда за этот месяц. Поймано тестом, закреплено регрессионными тестами.
3. Названия культур в части выпусков записаны строчными («семена подсолнечника») и не сопоставлялись.
4. Заголовки вида «( апрель 2023г.)» и «Май 2025)» не разбирались: в архиве терялись три месяца.
5. В моём собственном промежуточном отчёте цена пшеницы в СКО была неверно приписана (столбцы Павлодарской области); корректное значение за сентябрь 2026 — 80 223 тг/т, оно закреплено тестом.

**Присоединение к районному master:** по (область, культура, год) и только для отдельных культур. Для каждой строки считаются цена сезона уборки (август–октябрь), послеуборочная цена (ноябрь–декабрь), число месяцев в каждой, цена прошлого года (известна на момент посева), изменение к прошлому сезону и отношение цен подсолнечник/пшеница. Послеуборочное окно добавлено, потому что цены подсолнечника в августе–октябре почти не публикуются (в октябре — никогда).

**Ограничения:** ряд короткий (4 уборочных сезона), поэтому цены есть только за 2022–2025 (~12% строк); у ячменя в Акмолинской области и у подсолнечника много пропусков из-за конфиденциальных ячеек; кукурузы по трём областям в источнике нет; цен по районам и затрат нет.

## 3. Обеспечение качества данных (Data Quality Assurance)

Методология сбора построена на принципе: **ни одно число не считается верным, пока не подтверждено независимой проверкой** — либо сверкой с сырым ответом источника, либо перекрёстной сверкой между независимыми источниками, либо сопоставлением с общеизвестными доменными фактами.

**Реализованные механизмы валидации:**
1. **Кросс-валидация регион↔нация (скрипт 07):** сумма региональных данных (05) не должна превышать национальный итог (FAOSTAT, 01) и должна оставаться стабильной год к году. Именно этот механизм поймал баг с кодом страны (Эстония вместо Казахстана) — единственный способ, которым эта ошибка вообще могла быть обнаружена без ручного знания реальных объёмов производства.
2. **Кросс-валидация район↔область (встроена в скрипт 05):** сумма `production_ton` по районам должна совпадать со строкой "область целиком" для каждой комбинации (регион, культура, год). На 2026-09-10: **371 из 375 проверенных групп (98.9%) совпадают в пределах допуска 2%**; 4 расхождения — второстепенная культура (кукуруза) в Костанайской области с абсолютными объёмами в сотни-тысячи тонн на всю область, где пара тонн округления даёт заметный процент — не признак ошибки, задокументировано явно.
3. **Проверка правдоподобия по доменным фактам:** каждое исправление сверялось с независимо известными фактами — реальная площадь пшеницы в Казахстане (~10–13 млн га, не 130 тыс.), климатическая норма осадков степной зоны (~350–400 мм/год), физические границы pH (0–14) и долей гранулометрии (сумма = 100%), известные засушливые годы (1991, 1998, 2010, 2012, 2021–2022 — во всех случаях данные после исправления показывают ожидаемое снижение урожайности/осадков), и географический факт о "северном зерновом треугольнике" (Акмолинская+Костанайская+СКО дают ~77% пшеницы Казахстана по независимой FAOSTAT-сверке).
4. **Автоматическая защита от повторения бага с кодом страны:** `01_faostat.py` теперь проверяет, что полученное название страны действительно содержит "Kazakhstan", и падает с понятной ошибкой, если нет — вместо того чтобы молча доверять числовому коду.

5. **Автоматические тесты данных (`tests/`, 84 теста, `python -m pytest`).** Проверяют физические границы (урожайность, осадки, температура, pH, цены в тенге за тонну), уникальность ключей и координат, сверку суммы районов с областью (допуск 2%), отсутствие утечки из будущего в лагах, согласованность словаря данных с датасетом, а также чистые функции разбора. Каждая найденная в ревизии ошибка закреплена регрессионным тестом. Эффективность проверена вручную: шесть искусственно внесённых поломок (код страны Эстонии, осадки без поправки на дни, дублирующиеся координаты, урожайность 1.6 млн кг/га, pH без `d_factor`, сдвиг лага) каждая роняет хотя бы один тест.
6. **Сверка выбранных значений с исходными файлами.** Для региональных цен значения из листа 5 за сентябрь 2026 сверены с исходным xlsx (страна и три области зафиксированы в тесте).

**Итог ревизии (2026-09-09/10):** обнаружены и исправлены баги в 4 из 10 тогдашних скриптов (01, 03, 04, 05 — причём в 05 несколько независимых ошибок). Ни один баг не был найден предположением — каждый подтверждён прямой проверкой сырого ответа API/файла источника.

**Итог ревизии районного уровня (2026-10-05):** при построении скриптов 12–16 и тестов найдены и исправлены: подмена координат Енбекшильдерского района (12), завышенное испарение над озёрами (13), «зимняя» температура с декабрём после уборки (13), ошибки единиц площади в 393 строках (помечены в 15), формат `.xls` старых выпусков, слитное написание региона, регистр названий культур и заголовки месяцев в 16. Часть проблем найдена именно тестами, а не просмотром данных.

## 4. Известные ограничения методологии

Перечислены явно, а не скрыты — это соответствует принципу прозрачности, применённому ко всей остальной методологии:

1. **Рапс** — ни одна из трёх целевых областей не публикует данные по рапсу регионально. Единственный источник — национальный FAOSTAT (без региональной разбивки).
2. **Ячмень и кукуруза Акмолинской области** — доступны только на уровне группы "зерновые и бобовые" целиком, не как отдельные культуры (в отличие от пшеницы и подсолнечника, для которых нашлась встроенная разбивка — см. §2.5).
3. **Внутренние цены (08/09) — короткая история.** 12 недель (с 25.05.2026) — меньше одного полного сезонного цикла, недостаточно для самостоятельной time-series модели (ARIMA/Prophet и т.п.). Рекомендуемый подход: основную модель цены обучать на длинной истории (World Bank Pink Sheet, FAOSTAT producer price), а внутренний спред использовать как дополняющий/корректирующий признак на последних неделях, а не как самостоятельный прогнозный ряд.
4. **Цены (08/09) и районные данные (05).** Внутренние цены Зернового союза (08/09) по-прежнему не объединяются с районными данными: у них нет региональной оси и всего ~12 недель истории (с 25.05.2026). Однако региональные цены производителей stat.gov.kz (§2.12, скрипт 16) существуют по областям и культурам с октября 2022 года и **присоединены** к районному master за 2022–2025 (область × культура × год). Это 4 года, поэтому выводы о влиянии цены осторожны. Цен по районам и данных о затратах по-прежнему нет. Иллюстративный демо-скрипт `10_district_price_snapshot.py` соединяет последний год урожая с последней неделей цены — это осознанный date-mismatch для демонстрации механики, **не пригодный как компонент научной методологии**.
5. **Оперативные данные МСХ РК за 2024 год исключены из пайплайна.** Изначально присутствовали в виде жёстко прописанных в коде чисел без проверяемой ссылки на первоисточник — при ревизии не найдено подтверждающего пресс-релиза, поэтому файл удалён целиком, а не оставлен с пометкой "непроверено".
6. **Климат и почва — теперь на уровне района (скрипты 13–14), но это приближение.** Климат — среднее по окну ±0.2° вокруг центроида района, а не зональная статистика по полигонам границ района; полигонов границ в пайплайне нет. Координаты — центроиды из OSM (не административные центры), проверенные по bbox области. Почва статична (одно значение на район на все годы) и различает районы, но не годы. Климатические признаки по месячным средним ERA5-Land не видят экстремумов внутри месяца (заморозки, суховеи), а потенциальное испарение у озёр недостоверно (§2.10). Областной `master_dataset.csv` по-прежнему содержит климат и почву, одинаковые для всех областей.
7. **Область охвата — три области осознанно.** Рекомендательная система строится для Акмолинской, Костанайской и Северо-Казахстанской областей (зерновой пояс); выводы нельзя переносить на другие области.
8. **Ошибки единиц в посевной площади (`area_suspect`, 393 строки)** и расхождение урожайности с `сбор/площадь` в 15% строк (см. §2.11): `area_ha` как признак без фильтра использовать нельзя.
9. **Нет данных о затратах** (себестоимость, топливо, удобрения по регионам) и о ценах по районам: для рекомендательной системы это основной пробел. Возможное дополнение — таблица stat.gov.kz «Индекс цен приобретения продукции сельхозпроизводителями».

## 5. Воспроизводимость

Все скрипты идемпотентны и кэшируют промежуточные результаты (сырые файлы источников — в `output/*_cache/`), что позволяет безопасно перезапускать пайплайн без риска дублирования запросов к источникам. Полный порядок запуска — см. `README.md`, раздел "Быстрый старт".

**Рекомендация при использовании любых чисел из этого пайплайна в тексте диссертации:**
1. Убедиться, что использованная версия файлов пересобрана после 2026-10-05 (дата последней ревизии районного уровня).
2. Прогнать `07_validate_regions_vs_national.py` после любого повторного запуска скриптов 01 или 05.
3. Для районного уровня — свериться с выводом встроенной проверки сумма(районы)==область при каждом запуске `05_kaz_stat.py`.
4. После любой пересборки запускать `python -m pytest`; при добавлении столбца в районный master — обновить описание в `17_data_dictionary.py` (тест `test_dictionary.py` упадёт, если описания нет).
5. Не использовать `output/10_district_price_snapshot.csv` как источник фактов о конкретном годе — это демонстрационный, а не валидированный слой (см. §4, пункт 4).
